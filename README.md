# UKT ZED Classification Agent

Агент добирає код УКТ ЗЕД для товару з офіційного митного тарифу
та пояснює логіку вибору.

## Ключове архітектурне рішення

Модель отримує коди **виключно** через інструмент пошуку по довіднику.
Повернути код, якого немає в тарифі, вона структурно не може — це не
питання промпту, а питання того, звідки взагалі беруться дані.

## Пошук

Гібридний, по 11 005 позиціях тарифу:

- **BM25** — власний інвертований індекс у пам'яті, по термінології тарифу
- **char-TF-IDF** — розріджена матриця sklearn, стійка до різних формулювань
  і словоформ в описі товару
- **щільний векторний** — intfloat/multilingual-e5-large

Векторної бази немає свідомо. Ембединги лежать одним numpy-масивом
11005 × 768, пошук — множення матриці на нормалізований вектор запиту,
тобто косинусна схожість повним перебором. На 11 тисячах векторів це
частки мілісекунди. Наближені індекси на кшталт HNSW починають
окупатися від сотень тисяч векторів — тут вони додали б залежність
та інфраструктуру без виграшу.

**Умови переходу на pgvector:** корпус росте до сотень тисяч чанків
(Пояснення, класифікаційні рішення ДМС), потрібні фільтри по метаданих,
або пошук треба масштабувати окремо від застосунку.
