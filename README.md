# УКТ ЗЕД RAG-агент — локальний запуск (Windows)

**LLM-шар:** DeepSeek `deepseek-v4-flash` (нативний OpenAI-сумісний API, tool calls).
**Ретривер:** локальний, офлайн, без жодного API — BM25 + char-TF-IDF + e5-ембединги.

## Що всередині
- `uktzed_retriever.py` — гібридний ретривер (BM25 + char-TF-IDF + e5, злиття RRF)
- `uktzed_agent.py` — LLM як ОПІ-шар над ретривером; `--selftest` перевіряє все без API-ключа
- `uktzed_api.py` — FastAPI-сервіс (`POST /classify`, `GET /health`, `GET /` віддає демо-сторінку)
- `uktzed_demo_live.html` — демо-UI
- `uktzed_nodes.jsonl` — корпус: 17 285 вузлів, 11 005 листів, 14 719 кодів
- `uktzed_e5_cache.npy` — готові ембединги (11005 × 768, e5-base); кеш валідний, перерахунку НЕ буде
- `parse_uktzed.py` — парсер вихідних HTML Митного тарифу
- `uktzed_eval.py` + `uktzed_eval_seed.jsonl` — оцінка якості пошуку

## Крок 1 — встановлення
```cmd
cd <шлях-до-папки-проєкту>
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python uktzed_agent.py --selftest
```
`.venv` треба створити один раз. Далі в кожній новій консолі — лише `.venv\Scripts\activate`.
Очікувано: `selftest OK: пошук, верифікація, відхилення фейку, повний цикл, OpenAI-формат — усе працює.`

## Крок 2 — ключ DeepSeek
Скопіюйте `.env.example` → `.env` і впишіть ключ туди (файл у `.gitignore`, у репо не потрапить):
```
DEEPSEEK_API_KEY=sk-...
```
Агент читає `.env` сам. Альтернативно — змінна середовища:
```cmd
set DEEPSEEK_API_KEY=sk-...
```
Потім:
```cmd
python uktzed_agent.py
```

## Крок 3 — вебсервіс + демо-сторінка
```cmd
set DEEPSEEK_API_KEY=sk-...
set UKTZED_DENSE=1
python -m uvicorn uktzed_api:app --host 127.0.0.1 --port 8000
```
Відкрити http://127.0.0.1:8000

## Режим --dense (важливо для якості)
Без e5 на запит «жіноча вовняна сукня» лексика віддає ТКАНИНИ (група 55), а не готовий виріб.
e5 — основний ранкер (вага 1.3 проти 0.7/0.4):
```cmd
pip install -r requirements-dense.txt
python uktzed_agent.py --dense
```
Перший запуск завантажить `intfloat/multilingual-e5-base` (~1.1 ГБ, з torch ~2.5 ГБ).
Ембединги корпусу вже пораховані — модель потрібна лише для кодування запиту.
Windows + Python 3.14: torch 2.13.0 має cp314-колеса.

**DeepSeek не має embedding-моделі**, тому ембединги лишаються локальні (e5). Це не мінус:
працює офлайн, безкоштовно, без затримки мережі.

## Якість пошуку: заміряно
`python uktzed_eval.py --k 20 [--dense]`, 15 кейсів сіду:

| exact10 | лексика | + e5 |
|---|---|---|
| recall@20 | 86.7% | **93.3%** |
| top-1 | 46.7% | 53.3% |
| top-5 | 46.7% | **80.0%** |
| MRR | 0.501 | **0.651** |
| RECALL_MISS | 2 | **1** |

Два висновки, зашиті в код:
1. `CANDIDATES_FOR_LLM = 15` (було 10). З e5 еталон у топ-10 у 86.7% кейсів, у топ-15 — 93.3%.
   Обрізка на 10 викидала знайдені ретривером коди (напр. «жіноча сумка», еталон 11-й).
   Перевизначається через `UKTZED_CANDIDATES`.
2. Промт вимагає **переформулювати жаргон мовою тарифу** і шукати ще раз (до 3 спроб).
   «Підводний акустичний маяк-пінгер»: як є — еталон поза 5807-м місцем; «прилад навігаційний» —
   10-те місце вже на голій лексиці. Тариф не знає торгових назв і сленгу.

⚠️ 15 кейсів — мало. Розширюйте `uktzed_eval_seed.jsonl`, перш ніж вважати цифри стабільними.

## Офіційне найменування проти переказу
`finalize_code` повертає `official_chain` — рівні тарифу **дослівно** (товарна позиція → лист),
без Розділу й Групи. Промт вимагає цитувати їх як є, а власний переказ давати окремим рядком
«Простими словами». Причина: справжня назва `6403190000` у законі — буквально `- - інше`,
і в декларації має стояти офіційний ланцюжок, а не зручний парафраз моделі.

## Змінні середовища
| Змінна | Значення |
|---|---|
| `DEEPSEEK_API_KEY` | ключ DeepSeek (обов'язково для діалогу) |
| `UKTZED_MODEL` | типово `deepseek-v4-flash`; можна `deepseek-v4-pro` |
| `UKTZED_BASE_URL` | типово `https://api.deepseek.com` |
| `UKTZED_DENSE` | `1` — увімкнути e5 у вебсервісі |
| `UKTZED_W_BM25` / `UKTZED_W_CHAR` / `UKTZED_W_DENSE` | ваги ранкерів у RRF (для експериментів) |

## Ваги ранкерів
Заміряно на `uktzed_eval_seed.jsonl` (15 кейсів, `python uktzed_eval.py --k 20`):

| режим | ваги bm25/char | recall@20 | top-1 | MRR |
|---|---|---|---|---|
| лексика, було | 0.7 / 0.4 | 66.7% | 40.0% | 0.454 |
| лексика, стало | 0.5 / 1.3 | **80.0%** | **46.7%** | **0.497** |

Причина: char n-gram ловить словозміну («сукня» → «сукні» в тарифі), BM25 на точній формі
промахується. У кейсі «жіноча сукня з вовни» char ставив еталон на **1-ше місце**, BM25 — на 52-ге,
а стара вага 0.7 проти 0.4 давала перемогти BM25, і еталон вилітав з топ-20.

⚠️ 15 кейсів — мало, різниця це 2 кейси. Ваги міряйте на ширшому наборі, перш ніж вважати фінальними.
З увімкненим e5 ваги лишились як були (0.7 / 0.4 / 1.3).
